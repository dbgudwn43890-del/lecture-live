# 실시간 답변의 PDF·채팅 맥락 연결

## 원인과 변경

기존 `/api/live-assist`에는 최근 음성 전사와 이전 자동 답변만 전달됐다.
일반 질문의 자료 검색 경로와 별개여서, 이력서를 업로드해도 자동 답변은
해당 자료와 사용자가 채팅으로 설명한 면접 조건을 참고하지 못했다.

- 서버가 현재 사용자·현재 수업의 저장된 자료를 매 요청마다 조회한다.
  보통 길이의 이력서는 저장된 텍스트 전체를 포함하며, 큰 자료는 추가
  문자 검색으로 관련 내용을 찾는다. 전체 자료 문맥은 16,000자로 제한한다.
- 클라이언트는 실제 전송한 일반 채팅 중 완료된 최근 메시지를 최대 12개,
  합계 6,000자로 전달한다. 미전송 초안·생성 중 메시지·자동 답변은 제외한다.
- 이력서의 실제 역할·행동·성과와 채팅의 면접 조건을 이용해 바로 말할 수
  있는 답을 작성하도록 지침을 수정했다. AI가 만든 예시를 사용자의 이력으로
  오인하거나 회사·수치·경력을 지어내지 않도록 명시한다.
- WAIT 후 PDF 추가·삭제나 보낸 채팅이 바뀌면 같은 발화도 한 번 재검토한다.
  자동 답변 자체는 새 문맥 변경으로 처리하지 않는다. 직접 보낸 질문 처리 중에는
  새 자동 요청을 미루며, 이미 진행 중인 자동 스트림은 유지한다.
- 첨부 자료 조회 실패·빈 색인·5초 시간 초과는 구체적인 오류로 알린다.
  자료를 읽지 못한 채 없는 것으로 취급해서 답하는 것을 막는다.

## 접근·비용·녹음

기존 검증된 관리자 계정 제한, 수업 소유권·녹음 상태·크레딧 검사와 요청
제한을 유지한다. 서버 조회에는 사용자와 수업/문서 소유 조건이 적용된다.
PDF 원본을 다시 다운로드하거나 추가 임베딩·모델 호출을 하지 않는다.
모델 입력이 증가하므로 해당 자동 응답의 입력 토큰 비용은 늘 수 있다.

자료는 최대 20개, 문서별 첫 12개 청크와 필요 시 추가 검색 8개를 읽는다.
최대 4개 조회를 병렬 처리하고 전체 조회에 5초 제한을 둔다. 추가 검색은
이미 읽은 청크를 제외한다. 일부만 포함됐으면 그 범위를 모델에 명시한다.
큰 문서의 문자 검색은 모든 의미상 관련 내용을 찾는다는 보장은 없다.
자료 문맥은 추출된 텍스트이며 PDF 시각 요소를 새로 분석하는 기능은 아니다.

마이크·PCM·STT 토큰·릴레이·환경 변수·DB 스키마는 바꾸지 않았다.
실시간 답변은 기존 전사 스트림을 사용하며 별도 녹음을 만들지 않는다.

## 검증 및 배포

- 합성 이력서의 마지막 페이지, 새 자료 추가/삭제, 다른 계정·수업 격리,
  큰 자료 뒷부분 검색, 예산·동시성·시간 제한, 실패 처리를 회귀 검증했다.
- API 테스트에서 실제 전달되는 모델 입력에 서버 자료와 보낸 채팅이
  포함되는지 확인했다. 클라이언트가 위조한 자료 필드는 무시한다.
- 같은 발화의 PDF/채팅 변경 재검토, 중복 호출 억제, 직접 질문 우선,
  자동 답변의 재귀 호출 방지, 수업 전환 시 문맥 분리를 검증했다.
- 로컬 실제 HTTP의 CSP·마이크 정책·릴레이 건강 상태 사전 검사를 통과했다.
  사용 중인 녹음을 중단하거나 새 실제 음성·유료 모델 평가를 실행하지 않았다.

고정된 배포본에서 전체 테스트 **605개**, 타입 검사와 diff 검사를 통과했다.
후보의 소스 334개 해시가 배포 입력과 모두 일치했고, 자료·실시간 답변·STT
토큰 API는 비로그인 요청을 모두 HTTP 401로 차단했다.

승격 후 운영 녹음 사전 검사도 통과했다. 사용자 확인이 끝난 PDF Unicode
