# Review note quality checks

The note is organized from lecture evidence before conversation is curated.
Progress requests such as “여기까지 요약” and “what did I miss?” do not become
student learning questions, even when their saved replies contain useful content.
Topic-specific summaries, mixed requests, and short conceptual follow-ups remain
eligible. `isLectureStatusRequest` only recognizes unambiguous whole utterances;
the existing generation handles contextual cases without another model call.

Every Q ID must appear exactly once in a QA group or an explicit exclusion.
Validation checks original utterances, not model-rewritten labels. Unsupported
output fails without replacing the previous note. Existing saved notes are not
silently rewritten; use **Regenerate** to apply the new curation.

Lecture blocks require T/M evidence. Tables, steps, diagrams, code and formulas
are selected for the content; there is no infographic quota. Relations described
in words can be diagrammed, but invented data and unsupported links cannot.
Structured prose is plain text so shell operators and wildcards survive display
and printing. Code blocks retain their exact whitespace. Practice labels must
contain the actual question, separately from its answer.

Saved AI answers remain available in the original-answer disclosure. Valid
structured charts and practice questions are reused directly beside the QA
explanation, including their original values, rather than regenerated by a model.
PDF output omits the chat archive when a curated explanation exists; legacy notes
without one retain their original answers. This preserves the sole explanation
in old notes instead of deleting it to reduce page count.

Run offline regression/evaluation checks:

```sh
npm run eval:notes
node --experimental-strip-types --experimental-test-module-mocks --test app/lib/lecture-note*.test.ts app/api/lecture-notes/route.test.ts app/classroom/lecture-note-render.test.ts app/classroom/note-*.test.ts
npm run typecheck
```

Run the synthetic live cases with the configured API key (uses paid model tokens):

```sh
npm run eval:notes -- --live --language all --output /private/tmp/lecue-note-eval.json
```

The live evaluation uses the production prompt, schema and validator with
`store: false`. It tests Korean and English curation, grounding IDs, code symbols,
practice numbers, and saved-answer fidelity. It never reads a user's lecture or
database. The default dry run checks fixtures and the assertions themselves,
not model quality. Passing either check is not proof of general factual accuracy
or good PDF pagination: also inspect representative generated notes and print
output. Keep generated reports outside the repository.
