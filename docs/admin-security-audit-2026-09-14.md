## 수정한 보안·운영 문제

- 관리자 페이지 렌더링 전에 서버의 실제 인증 결과와 관리자 허용 목록을 확인한다. 일반 사용자는 대시보드 구성 요소를 렌더링하지 않는다. API도 독립적으로 검사한다. 이전 API 자체가 공개됐다는 의미는 아니다.
- 관리자 인증은 `getUser()`의 검증된 이메일 계정에 한정한다. 클라이언트 상태나 사용자가 수정할 수 있는 메타데이터의 관리자 표시는 사용하지 않는다.
- `ADMIN_USER_IDS` 설정 시 이를 우선한다. 당시 운영 설정은 `ADMIN_EMAILS` 기반이었다.
- 지급에는 동일 출처·JSON·본문 크기·대상·수량·기간·사유 검증, 별도 속도 제한, 서버가 결정한 지급자 식별자를 적용했다.
- 지급 검토 단계와 고정 요청 번호를 사용한다. 요청이 끊기면 같은 번호로 재시도하며 DB에서 중복 지급과 서로 다른 요청 내용의 재사용을 막는다. 지급과 감사 로그는 원자적으로 저장된다.
- 관리자 RPC/감사 테이블은 일반 사용자에게 공개하지 않는다. API 응답은 `private, no-store`다.
- 사용자 검색·페이지 이동과 DB 집계로 조회 범위를 명확히 했으며 조회 실패를 0건으로 위장하지 않는다.
- 녹음 이상 신호는 남용 판정으로 표현하지 않는다. 가입 전송 시도는 GA4 수신과 구분한다.
- 결제 Permissions-Policy의 잘못된 URL 문법을 수정했다.
