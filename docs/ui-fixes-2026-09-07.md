## 다음 작업자가 이어갈 순서

1. Chrome에서 Lecue 탭을 전면에 놓고 직접 온라인 시작 버튼 클릭. 테스트 영상 탭과 탭 오디오를 선택해 영상 표시·실제 STT 수신 확인. 실패하면 `getDisplayMedia` 원본 오류를 확인해 원인 수정. 인증이나 캡처 권한을 우회하지 않는다.
2. 강의 화면 ↔ 스크립트 반복 전환, 전체 화면, 수동 일시정지/재개, 브라우저 공유 중단/재선택, 종료 후 트랙 해제 검증. 미리보기 컴포넌트 해제가 원본 공유 트랙을 중단하면 안 된다.
3. 실제 질문이 있는 세션으로 말풍선·시점 링크·대화 후 placeholder, 한/영·좁은 화면 확인. 질문을 새로 보내는 검증은 실제 API 사용과 데이터 저장이 발생함을 고려한다.
4. `docs/online-lecture-qa.md`의 오프라인 과금 오차와 아직 빈 수동 인수 항목 검토. 이번 UI 빌드 통과는 해당 과금/오디오 인수 검증을 대체하지 않는다.
5. Paddle은 사용자가 직접 담당하며 현재 개발 투두와 UI 배포의 선행 조건에서 제외한다.

## Paddle 연결 참고 자료 — 사용자 담당, 현재 개발 투두 아님

사용자가 심사와 Live 계정 준비를 완료해야 한다. 키 값을 채팅이나 문서에 기록하지 말고 배포 환경의 비밀 설정에 입력한다.

현재 코드가 요구하는 설정은 다음과 같다(대시보드 UI 명칭을 새로 조사한 문서가 아닌 코드 기준 체크리스트).

- 처음에는 `BILLING_ENABLED=false`로 유지.
- 서버 `PADDLE_ENVIRONMENT=production`, 클라이언트 `NEXT_PUBLIC_PADDLE_ENVIRONMENT=production`. 이 코드에서는 `live` 문자열을 사용하지 않는다.
- Live 서버 API 키 → `PADDLE_API_KEY`, Live 클라이언트 토큰(`live_` 접두사) → `NEXT_PUBLIC_PADDLE_CLIENT_TOKEN`.
- Live 웹훅 목적지 `/api/billing/webhook`의 서명 비밀 → `PADDLE_WEBHOOK_SECRET`.
- 코드가 처리하는 이벤트: `transaction.completed`, `subscription.*`, `adjustment.created`, `adjustment.updated`. 필요한 세부 구독 이벤트는 라우트와 구독 처리 코드를 대조해 선택.
- 현재 `app/lib/plans.ts`의 상품과 가격을 확인한 뒤 Live price ID 네 개를 `PADDLE_MONTHLY_V2_PRICE_ID`, `PADDLE_SEMESTER_V2_PRICE_ID`, `PADDLE_ANNUAL_V2_PRICE_ID`, `PADDLE_TOPUP_V2_PRICE_ID`에 연결. Sandbox ID를 재사용하지 않는다.
- 기존 Sandbox 고객·주문과 Live 고객·주문이 섞이지 않는지 확인. 웹훅 중복/지연, 결제 금액·상품 불일치, 취소·환불·차지백, 크레딧 중복 지급 방지 검사 후 `BILLING_ENABLED=true`와 재배포 진행.
- 실제 결제 검증은 사용자가 수행하며 결제 결과와 크레딧 지급을 대조한다. 현재 실결제 개통 완료 상태가 아니다.
