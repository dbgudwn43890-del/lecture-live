# 수업 준비·질문·복습 노트 수정

## 변경 내용

- 자료 업로드로 수업 초안을 만들 때 입력한 제목을 함께 저장한다. 생성·저장 도중 입력한 최신 제목이 이전 응답에 덮이지 않도록 한다.
- 같은 수업의 이름 저장 요청은 순서대로 처리한다. 자동 저장·저장 상태·재시도를 제공하며, 실패 시 입력값을 유지한다. 수업 이동 전 최신 이름 저장을 마치고, 저장 중에는 수업 전환과 새 녹음이 겹치지 않게 한다.
- 현재 수업의 읽기 완료 자료가 있으면 녹음 없이 기존 질문창을 사용할 수 있다. 별도 모드는 추가하지 않는다. 읽기 완료 후 준비 화면에서 질문창으로 이어지며, 이후 같은 초안에서 녹음을 시작해도 자료 문답을 유지한다.
- 자료만 사용한 답변은 강사의 발언으로 표현하지 않도록 한·영 지침을 보강한다. 기존 인증·소유권·크레딧 검사는 유지한다.
- 녹음 파일 업로드는 인증된 API에서 서비스 준비 상태를 확인한 후에만 파일 선택을 허용한다. 준비되지 않았거나 상태 확인이 실패하면 사유·대체 경로·재확인 동작을 표시한다.
- 현재 multipart 업로드의 Vercel 파일 상한을 4,000,000바이트로 안내·검증한다. 긴 파일명에도 일정한 재시도 식별자를 사용하며, HTTP 413·401을 구분한다. 대용량 직접 업로드 구조는 이번 변경에 포함하지 않는다.
- 복습 노트는 질문 제목을 다듬되, 저장된 AI 답변을 서버에서 원문으로 붙인다. 채팅과 같은 렌더러로 연습문제·정답·그래프를 재사용한다. 기존 노트에는 다시 만들기가 필요하며, 보존된 답변은 원래 언어를 유지한다.
- 수업 검색 결과가 비었을 때 안내를 표시한다.

## 녹음 영향과 변경 전 기준

영향 단계: 준비 화면의 수업 제목·초안 생성, 녹음 시작 버튼의 전환 잠금, 업로드 사전 준비 확인·요청 검증, 녹음 전 질문 대화의 보존. PCM·전송 큐·Worker·토큰 발급·릴레이·환경 설정은 수정하지 않았다.

수정 전 `npm run check:recording`은 제한된 실행 환경에서 앱·릴레이 fetch가 실패했다. 네트워크 접근이 허용된 실행으로 같은 명령을 실제 localhost:3000에 다시 실행했고 CSP, WebSocket, AudioWorklet, Worker, microphone/display-capture Permissions-Policy, 릴레이 health가 모두 통과했다. 서버 자체의 기존 실패로 기록하지 않는다.

## 검증

- 변경 후 같은 실제 로컬 서버에 `npm run check:recording`을 실행해 모든 항목 통과.
- 전체 단위·API·컴포넌트 회귀 테스트 859개 및 typecheck 통과. 최종 로그: `/private/tmp/lecue-learning-flow-final-tests.log`.
- 릴레이 단위 테스트 26개 통과. 전송·큐·Worker 변경이 없어 workerd 네트워크 smoke는 이번 작업에서 재실행하지 않았다.
- 업로드 관련 검사는 공급자·DB 모킹과 실제 로컬 FFmpeg 합성 WAV 디코딩을 포함한다. 실제 외부 음성 변환 완료를 뜻하지 않는다.
- 노트 회귀는 강의 예제 75점으로 답을 바꾸는 모델 출력을 넣어도 원래 연습문제의 20명×80점 + 10명×50점, 정답 70점, 원래 그래프 데이터가 유지됨을 확인한다. 실제 노트 컴포넌트 렌더링도 검사한다.
- 로그인된 Chrome의 실제 로컬 화면에서 녹음 파일 사전 차단·안내, 입력 제목 표시를 확인했다. 자료 첨부 브라우저 검증은 확장의 파일 접근 권한 제한으로 완료하지 못했다. 이 경로는 실제 컴포넌트 callbacks와 API를 각각 모킹해 검증했다.
- 실제 마이크·탭 소리 인식, 시작·일시정지·재개·종료의 실제 오디오 검증은 이번 작업에서 수행하지 않았다. 실행 중인 서버나 기존 녹음 세션을 재시작·중단하지 않았다.
- 배포하지 않았다. 운영 URL 점검·배포 소스 일치 검증은 배포 시 별도로 필요하다.
