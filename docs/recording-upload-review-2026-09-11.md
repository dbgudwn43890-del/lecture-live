# 녹음 파일 업로드 검토 — 2026-09-11

사용자 증상: 파일 업로드 자체가 실패함. 실제 파일명·크기·형식·화면 오류 문구는 아직 제공되지 않아 사용자 건의 원인을 하나로 단정하지 않는다.

## 확인한 결함

### P1 — 운영 서버의 요청 크기 제한 때문에 일반 녹음 파일을 업로드할 수 없음

- `app/classroom/workspace-client.tsx:731,744`: 원본 파일 전체를 multipart 요청으로 `/api/lecture-audio`에 보낸다.
- `app/api/lecture-audio/route.ts:112`: 서버가 전체 파일을 수신한 뒤 검증한다. `MAX_AUDIO_BYTES`는 1GiB지만 그 전에 Vercel의 4.5MB 요청 제한이 적용된다.
- 실제 운영 HTTP 재현: 로그인·쿠키 없이 합성 데이터 요청만 전송했다. 1KB는 `401 SIGN_IN_REQUIRED`, 5MiB는 `413 FUNCTION_PAYLOAD_TOO_LARGE`와 `text/plain` 응답. 같은 요청은 localhost:3000에서 모두 앱의 `401`에 도달했다. 실제 파일 저장·음성 변환·크레딧 소비는 실행하지 않았다.
- 조치 방향: 인증·동의·사용량 제한을 통과한 업로드만 비공개 저장소에 직접 전송하고, 서버에는 업로드 식별자만 전달한다. 큰 파일은 재개 가능한 전송을 사용한다. 현재의 실제 오디오 디코딩·길이 검증·크레딧 예약·소유권 검사는 유지하고, 원본 및 변환 파일의 저장소 한도와 임시 디스크 용량까지 맞춰야 한다. 클라이언트가 전달하는 파일 길이를 신뢰하거나 파일을 공개하는 방식으로 우회하면 안 된다.
- 공식 근거: https://vercel.com/docs/functions/limitations , https://supabase.com/docs/guides/storage/uploads/standard-uploads

### P2 — 긴 파일명은 크기가 작아도 거절됨

- `workspace-client.tsx:738`: 파일명·크기·수정 시각을 연결해 재시도 식별자로 사용한다.
- `lecture-audio/route.ts:146`: 식별자가 100자를 넘으면 일반적인 잘못된 요청 오류로 거절한다.
- 재현: 87자 파일명으로 만든 식별자는 109자. 실제 POST 핸들러에 저장소·인증·공급자를 모킹하여 전달했을 때 `400`, `올바른 업로드 요청이 아닙니다.`가 반환되며 공급자 호출은 0회였다.
- 조치 방향: 원래 파일명은 표시용으로 보존하고, 재시도 식별자는 길이가 일정한 해시 등으로 분리한다. 재시도 시 중복 변환·과금 방지는 유지한다.

### P2 — 서버가 보낸 실패 원인이 화면에서 사라짐

- `workspace-client.tsx:746,754–769`: 응답을 JSON으로만 해석하고 HTTP 상태를 검사하지 않는다. 운영의 텍스트 `413` 응답은 JSON이 아니므로 일반 업로드 실패로 바뀐다.
- 조치 방향: HTTP 상태와 안전한 앱 오류 코드를 기준으로 크기 초과, 로그인 만료, 서버 오류를 구분한다. 원시 공급자 응답·토큰은 사용자에게 노출하지 않는다.

## 검증 범위

- 수정 전 실제 로컬 `npm run check:recording`: 모두 통과. 실제 음성 인식 성공을 의미하지 않는다.
- 업로드 API·콜백·오디오 변환 관련 기존 테스트: 35개 통과. 로컬 FFmpeg로 합성 WAV를 디코딩하는 검사 포함, Deepgram 호출·DB는 모킹.
- 임시 긴 파일명 재현 테스트: 기존 API 17개 + 재현 1개 통과. 실패 동작이 재현된 것이며 수정 후 회귀 테스트가 아니다.
- 관련 4개 소스 파일은 마지막으로 검증한 운영 배포 SHA1 목록과 일치했다.
- 운영의 실제 합성 HTTP 요청으로 Vercel 크기 제한을 확인했다. 사용자 오디오·DB 내용·비밀 키를 출력하지 않았다.
- 증거: `/private/tmp/lecue-upload-review-before.log`, `/private/tmp/lecue-upload-review-tests.log`, `/private/tmp/lecue-upload-repro-results.log`.

이번 작업은 검토와 재현이며 제품 코드 수정·배포는 하지 않았다.
