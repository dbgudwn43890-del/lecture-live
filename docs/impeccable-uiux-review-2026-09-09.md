# Lecue 디자인·UI/UX 검토

검토일: 2026-09-09. 검토만 수행했으며 제품 코드, 계정, 강의 데이터, 결제 상태는 변경하지 않았다.

## 결론

전면 재디자인보다 **읽기 품질 → 시작 안내 → 상태 전달 → 탐색 → 선택적 애니메이션** 순서가 적합하다. 차분한 녹색과 종이색, 여백, 질문 중심의 화면은 유지할 가치가 있다. 중앙 질문 화면과 하단 입력창을 유지하며, 별도의 상시 전사 패널을 되살리는 방향은 권하지 않는다.

## 방법과 범위

- [Impeccable](https://github.com/pbakaus/impeccable)의 공식 audit·animate 지침을 읽고 수동 적용했다. 로컬 실행 도구가 없어 자동 detector 및 정식 명령 실행 결과는 아니다. 독립 평가자 두 명이 필요한 정식 critique 절차도 실행하지 않았다.
- 운영 사이트의 랜딩·체험·로그인·플랜, 로컬 최신 강의실의 준비 화면·저장된 질문·기존 복습 노트를 브라우저에서 확인했다.
- 강의실은 데스크톱과 좁은 화면을 확인했다. 질문 화면은 DOM에서 390×844 CSS px 및 가로 넘침 없음을 측정했다. 노트는 433 CSS px에서 확인했다. 모든 페이지·모바일 기기를 테스트한 것은 아니다.
- 현재 소스와 제품 방향 문서를 대조했다. 기존 graphify 그래프는 파일 탐색에만 사용했으며, 이전 날짜의 그래프보다 현재 소스를 우선했다.
- 녹음 시작, 질문 전송, 업로드, 노트 재생성, 인증번호 발송, 결제는 실행하지 않았다. 해당 비동기 상태의 평가는 소스 기반 제안이지 실제 장애 재현이 아니다.
- 어두운 테마, 스크린리더 실사용, 가상 키보드, 모든 색상 대비, 성능 계측은 미검증이다. 접근성 인증이나 Lighthouse 점수로 해석하지 않는다.

## 유지할 부분

1. 랜딩의 “놓친 설명을, 수업이 끝나기 전에.”는 제품의 쓰임을 잘 압축한다.
2. 가입·녹음 없이 체험할 수 있고, 예시 데이터임을 설명한다. 체험 닫기와 Escape 복귀도 구현되어 있다.
3. 화면 전반의 녹색·종이색 톤이 이어지고, 업무 화면에 불필요한 장식이 적다.
4. 질문 화면의 중앙 읽기 영역과 고정 입력창은 강의 도중 사용에 적합하다.
5. 사용자가 위로 읽으면 자동 스크롤을 멈추는 기존 동작은 유지해야 한다.
6. 복습 노트는 요약·핵심·본문·출처·내 질문이 연결되고, 데스크톱 목차도 있다. 새 대시보드로 바꿀 필요가 없다.
7. 로그인은 입력 라벨, 비밀번호 보기, 복구 동선이 명확하다. 장식보다 현재의 단순함을 유지하는 편이 좋다.

## 우선순위별 개선

P1은 다음 개선 작업에서 먼저 처리할 항목, P2는 이어서 다듬을 항목이다. 모든 항목이 기능 오류라는 뜻은 아니다.

### 1. P1 · 답변의 마크다운 잔여 기호와 읽기 위계

**관찰:** 저장된 실제 답변에서 `**140~150%**`처럼 강조 기호가 화면에 남아 있었다. 긴 답변에는 여러 겹의 목록이 이어진다. 현재 본문은 14px, 절 제목은 13px로, 제목이 본문보다 작다.

**영향:** 설명 자체가 맞아도 미완성 출력처럼 보일 수 있다. 강의를 들으며 원하는 문장을 재빨리 찾기 어렵다.

**제안:** 원문과 렌더러를 함께 점검하고, 숫자·문장부호·한글 조사가 붙은 강조의 회귀 사례를 추가한다. 모든 별표를 정규식으로 제거하는 방식은 피한다. 본문 15–16px, 절 제목은 본문 이상 크기를 후보로 비교한다. 긴 설명은 첫 문장에 결론을 두고 필요한 근거가 이어지도록 한다. 중요한 설명 전체를 기본 접힘으로 숨기지는 않는다.

**관련:** `app/classroom/answer-markdown.ts:31`, `app/classroom/learning-answer.css:1`, `app/classroom/learning-answer.css:7`.

**확인 기준:** 동일한 저장 답변과 스트리밍 완료 결과 모두 기호 누출이 없고, 수식·코드·표는 보존된다. 390px 화면에서도 핵심 문장과 절 경계를 찾기 쉽다. 기호 누출의 정확한 원인은 이번 검토에서 확정하지 않았다.

### 2. P1 · 중요한 보조 정보와 조작 영역의 크기

**관찰:** 여러 보조 라벨·출처·피드백은 11–12px다. 데스크톱 사이드바의 검색·추가 버튼은 약 22×22px, 좁은 노트 화면의 PDF 저장·다시 만들기는 높이 약 29px였다.

**영향:** 절제된 디자인이 일부 기능에서는 찾기 어렵고 누르기 어려운 디자인으로 넘어간다.

**제안:** 아이콘 그림의 크기는 유지하되 클릭 영역을 늘린다. 데스크톱 보조 아이콘은 32px 이상, 터치가 중요한 컨트롤은 44px를 설계 목표로 삼는다. 출처·기록 상태처럼 판단에 필요한 보조 정보는 12–13px 이상 후보를 비교한다. 낮은 대비를 무조건 진하게 바꾸기보다 중요도별 위계를 유지한다.

**관련:** `app/classroom/workspace.css`, `app/classroom/lecture-note.css:4`, `app/classroom/lecture-note.css:41`.

**확인 기준:** 키보드 포커스가 명확하고 인접 클릭 영역이 겹치지 않는다. 작은 크기만으로 WCAG 위반이라고 단정하지 않는다. 간격 예외와 실제 대비는 별도 측정이 필요하다.

### 3. P1 · 수업 시작 화면을 “무엇을 누를까?” 중심으로

**관찰:** 큰 환영 문구, 별도 상단의 수업 이름, 언어 선택, 현장·온라인 시작 버튼으로 시선이 나뉜다. 시작 카드 자체에는 마이크와 Chrome 탭 소리의 차이를 설명하는 좋은 안내가 이미 있다.

**제안:** 환영 문구의 비중을 조금 줄이고 시작 선택을 중심에 둔다. 수업 이름은 선택 사항임을 명시하고 시작 동작 가까이 두는 구성을 검토한다. “한국어 + 영어”에는 “두 언어를 번갈아 말하는 수업”처럼 사용 상황을 한 줄로 설명한다. 모델명·공급자 선택은 전면에 내세우지 않는다.

**관련:** `app/classroom/workspace-client.tsx:1959`, `app/classroom/workspace-client.tsx:2152`, `app/classroom/language-choices.tsx:16`.

**확인 기준:** 처음 온 사용자가 언어와 입력 종류를 고른 뒤 바로 시작할 수 있다. 선택적인 이름 입력·자료 업로드를 필수 단계로 오해하지 않는다. 안내 문구는 실제 지원 정책과 일치해야 한다.

### 4. P2 · 랜딩 체험의 설명 부담과 실제 화면의 연결

**관찰:** 현재 체험은 통계학 표, PC·모바일 비율, 가중 평균, 앞선 근거, 비율 변경을 함께 보여준다. 상호작용은 제품 특성을 잘 드러내지만, 방문자가 통계 예제를 이해하는 데 먼저 집중할 가능성이 있다. 실제 사용 화면은 전사 패널 없이 질문에 집중한다.

**제안:** 첫 단계는 “놓친 말 한 문장 → 질문 한 문장 → 연결해 주는 답변”만 강조한다. 표와 비율 실험은 더 알아보기 단계로 둔다. 체험의 질문·답변·출처 표현을 실제 강의실과 맞추되, 실제 화면에 전사 패널을 다시 추가하지 않는다. “가입·마이크 없이 예시로 체험”을 체험 CTA 근처에도 짧게 둔다.

**관련:** `app/landing-page.tsx:44`, `app/landing-page.tsx:57`, `app/landing-interactions.tsx`.

**확인 기준:** 신규 사용자에게 30초 체험 후 “이 제품이 내 수업에서 무엇을 해주는가”를 물어 검증한다. 현재 예제가 전환율을 낮춘다는 주장은 아직 가설이다.

### 5. P2 · 자료와 비동기 상태를 행동 가까이에서 전달

**관찰:** 질문 입력창의 첨부 기능은 클립과 개수 배지로 압축되어 있다. 자료 상태·관리는 펼쳐야 자세히 보인다. 준비 화면에는 읽는 중·자료 준비됨 안내가 이미 있다.

**제안:** 사용 중 자료 추가 시 입력창 가까이에 “자료 읽는 중 → 자료 1개 반영됨”을 잠깐 명시하고 평상시에는 지금처럼 접는다. 녹음도 연결 중·소리 없음·기록 중·재연결을 구분하되 항상 큰 배너를 두지는 않는다. 답변 대기는 실제 단계만 표시하고 추정 진행률을 꾸미지 않는다.

**관련:** `app/classroom/workspace-client.tsx:1965`, `app/classroom/workspace-client.tsx:2137`, `app/classroom/workspace-client.tsx:2168`, `app/classroom/use-lecture-recorder.ts`.

**확인 기준:** 녹음·업로드·응답 요청을 실제로 테스트하여 상태 문구와 서버 상태가 맞는지 확인한다. 이것은 상태 표시가 전혀 없다는 지적이 아니라, 기존 피드백의 위치와 명확성을 개선하는 제안이다.

### 6. P2 · 모바일 복습 노트의 긴 문서 탐색

**관찰:** 데스크톱에는 고정 목차가 있으나 좁은 화면에서는 상단의 접히는 목차로 전환된다. 긴 노트를 내려 읽으면 다시 목차를 찾기 위해 위로 돌아가야 한다.

**제안:** 노트 헤더에 작은 “목차” 컨트롤을 유지하고 현재 절 이름을 함께 보여주는 방식을 검토한다. 목차 이동 후 해당 절에 짧은 배경 강조를 주면 도착 위치를 이해하기 쉽다. 읽던 위치를 유지하며 질문으로 돌아가는 동작도 확인한다.

**관련:** `app/classroom/lecture-note.tsx:164`, `app/classroom/lecture-note.css:37`, `app/classroom/lecture-note.css:114`.

**확인 기준:** 긴 노트 중간에서도 한 번의 동작으로 목차에 접근하고 원하는 절로 이동할 수 있다. 모바일 상단 고정 영역은 커지지 않아야 한다.

### 7. P2 · 플랜의 숫자를 수업 시간과 결제 방식으로 읽히게

**관찰:** 카드에는 이미 “매월 2,400 크레딧 · 강의 기록 40시간”과 자동 갱신 여부가 있다. 다만 현재 잔액, 신규 플랜의 월 지급 안내, 영어 플랜 이름, `credits` 표기가 함께 보인다. 질문·답변의 별도 차감 여부는 FAQ에 있다.

**제안:** 현재 이용 상태와 새 플랜 안내를 명확하게 분리한다. 비교 순서를 “월 기록 시간 → 이용 기간 → 실제 결제 총액 → 자동 갱신 여부”로 정렬한다. 크레딧 단위는 보조로 두고, 질문·답변 비용 정책은 주요 카드 근처에도 짧게 설명한다. 한국어 화면의 `credits`는 “크레딧”으로 통일한다. 무료 체험도 기간과 사용량을 같은 단위로 설명한다.

**관련:** `app/billing/billing-client.tsx:133`, `app/billing/billing-client.tsx:145`, `app/billing/billing-client.tsx:165`, `app/landing-page.tsx:111`.

**확인 기준:** 사용자가 오늘 결제할 금액, 매월 사용할 시간, 자동 재결제 여부를 FAQ 없이 구분한다. 정책 변경 제안은 아니며 실제 정책과 UI 안내의 정합성을 먼저 확인한다.

## 애니메이션 제안

시간은 구현 후보값이지 측정된 최적값이 아니다. Impeccable의 원칙대로 랜딩은 가치 이해를 돕고, 사용 화면은 상태와 위치를 설명하도록 구분한다.

| 위치 | 권장 동작 | 후보 시간 | 주의점 |
| --- | --- | --- | --- |
| 랜딩 체험 | 질문 선택 후 답변 등장, 관련 근거만 순차 강조 | 180–250ms | 매 스크롤마다 반복 등장시키지 않기 |
| 체험의 비율 실험 | 사용자가 바꾼 비율과 결과를 함께 전환 | 250–350ms | 표·최종 수치는 동작 없이도 이해 가능하게 |
| 자료 처리 완료 | 로딩 표시에서 완료 아이콘·문구로 교체 | 120–180ms | 실패를 완료처럼 보이게 하지 않기 |
| 녹음 상태 변경 | 상태 아이콘·문구를 짧게 전환 | 120–180ms | 음성 입력 신호는 실제 음량에 연결 |
| 노트·자료 패널 | 짧은 opacity와 소폭 이동 | 160–220ms | 포커스 이동·복귀, Escape가 우선 |
| 노트 목차 이동 | 이동한 절의 배경 강조 후 해제 | 600–800ms | 이동 자체를 기다리게 하지 않기 |
| 사이드바 접기 | 접히는 영역을 중심으로 짧게 전환 | 180–240ms | 답변 줄바꿈이 반복해서 바뀌는지 확인 |

현재 사이드바는 grid 열 너비·읽기 영역 최대 너비·본문 padding에 전환을 걸고 있다(`workspace.css:182`). 성능 저하를 측정한 것은 아니지만, 좁은 데스크톱에서 줄바꿈과 읽는 위치가 흔들리는지 확인할 후보이다. 문제가 보이면 본문 폭을 안정시키고 사이드바의 이동·투명도만 움직이는 방식부터 비교한다.

현재 음량 미터는 실제 입력 레벨을 사용하면서 반복 scale 애니메이션도 더한다(`globals.css:2624`, `use-lecture-recorder.ts:537`). 실제 입력 반응은 유지하고 무음에서도 살아 움직이는 장식은 줄이는 편이 상태 전달에 명확하다. 녹음 중 화면의 실제 관찰은 하지 않았다.

피할 것: 답변 타자 효과 추가, 글자 단위 등장, 상시 반짝이는 출처, 수업 중 반복 스켈레톤, 읽는 중 강제 스크롤, 근거 없는 진행률, 기본 전환만을 위한 새 애니메이션 라이브러리.

`prefers-reduced-motion`에서는 이동·반복 동작을 없애되 상태 텍스트와 완료 피드백은 유지한다. 기존 reduced-motion 처리와 자동 스크롤의 사용자 의도 보존은 회귀 방지 대상이다.

## 권장 실행 순서

1. 답변 렌더링의 확정 오류를 재현하고 수정한다. 함께 본문·제목 위계와 클릭 영역을 정리한다.
2. 시작 화면의 안내, 자료 반영 피드백, 모바일 노트 탐색을 개선한다.
3. 랜딩 체험을 한 단계 단순화하고 실제 질문 화면의 표현과 맞춘다.
4. 마지막에 필요한 상태 전환에만 모션을 넣는다.

완료 검증에는 390px·데스크톱, 확대 보기, 밝은/어두운 테마, 키보드 탐색, 동작 줄이기, 모바일 가상 키보드, 녹음 권한 거절·무음·연결 복구, 자료 실패, 답변 지연을 포함한다. 이번 검토에서 미실행한 항목을 통과한 것으로 간주하지 않는다.

## 설치 후 보충 검사와 개선 적용

사용자의 후속 요청에 따라 이전 전체 검토를 반복하지 않고, 자동 검출·강조 오류 재현·좁은 화면·테마 대비·포커스 복귀를 보충했다. Impeccable 4.3.1의 context는 현재 구현을 기준으로 부분 개선을 허용했다. 정식 critique나 전체 접근성 재인증은 수행하지 않았다.

### 실제 적용한 변경

- **한국어 강조 오류 수정:** `%`·괄호 뒤에 한글 조사가 붙는 문장을 기존 렌더러로 재현했다. [Streamdown 공식 CJK 플러그인](https://streamdown.ai/docs/plugins/cjk)을 연결해 원문을 바꾸지 않고 처리한다. 저장된 실제 강의의 답변 DOM에서는 남은 `**`가 0개였다. 회귀 테스트는 완성 문장과 모든 스트리밍 접두 구간, 기존 코드·수식·표·안전성 사례를 포함한다.
- **읽기 위계:** 질문 답변 본문을 14px에서 15px로, 절 제목은 본문보다 작지 않도록 조정했다. 절 위아래 간격도 분리했다.
- **조작 영역:** 사이드바 검색·추가 버튼을 데스크톱 32px, 모바일 44px로 확장했다. 모바일의 첨부·전송·후속 질문·노트 저장/재생성·출처 펼침도 최소 44px 기준으로 보완했다. 포커스 표시를 추가했다.
- **수업 준비:** 환영 제목의 크기·자간을 절제하고 언어·입력 방식 안내를 12px로 올렸다. 수업 이름의 placeholder에 선택 사항임을 표시했다. 언어 안내와 자료 완료 알림은 이미 존재하므로 중복 추가하지 않았다.
- **모바일 노트:** 본문 상단의 목차를 고정하고 현재 절을 표시한다. 항목 선택 시 목차가 닫히고 해당 절/질문으로 포커스와 읽기 위치가 함께 이동한다. 첫 확인에서 제목 가림을 발견해 여백을 보정했고, 최종 확인에서는 목차 아래 약 19px 간격으로 제목이 보였다.
- **모션:** 사이드바 조작 때 본문 폭·padding을 매 프레임 바꾸는 전환을 제거했다. 음량 미터는 실제 입력 레벨 반응만 남기고 반복 흔들림을 제거했다. 동작 줄이기에서는 임의의 0.01ms 전환 대신 즉시 상태 변경을 사용한다. 새로운 애니메이션 라이브러리는 추가하지 않았다.

중앙 질문 화면, 하단 입력창, 사용자가 위로 읽을 때 자동 스크롤을 멈추는 동작, 기존 브랜드와 랜딩 체험은 유지했다. 랜딩 예제의 대폭 단순화나 요금제 재구성은 실제 사용성 근거가 부족하므로 이번 부분 개선에 포함하지 않았다.
