# 수업 준비·자료·녹음 업로드 개선

2026-09-11 요청의 후속 구현. 개인정보처리방침 시행일은 사용자가 확정한 **2026-08-31**이다.

## 반영 내용

- 자료가 읽히면 별도 모드 없이 기존 질문창을 사용할 수 있다. 자료로 초안을 만들 때 입력한 제목을 보존하고, 자동 저장·재시도·화면 이동 전 저장을 처리한다.
- 자료 목록에 파일명·처리 상태·페이지 수·읽은 내용 미리보기·삭제·교체를 제공한다. 업로드하면 목록을 펼친다. 교체 파일을 먼저 읽고 성공한 뒤 기존 자료를 삭제하므로 실패 시 기존 자료를 유지한다.
- 검색 결과가 없으면 검색어를 포함한 안내와 지우기 버튼을 표시한다. 수업 목록에 날짜·시각·길이·질문 수를 표시한다.
- 질문 800자부터 카운터를 표시하고 1,000자에서는 최대 길이와 자료 첨부 안내를 표시한다.
- 시작 버튼 근처에 실제 마이크 이름·입력 음량·강의 언어·기록 및 크레딧 시작 시점 안내를 제공한다. 소리 확인은 직접 눌렀을 때만 실행하고 종료·장치 변경·수업 시작 시 해당 확인용 스트림을 해제한다.
- 설정 버튼을 준비·기록·종료 상태에서 같은 위치에 유지한다.
- 무료 체험의 600크레딧·14일·카드 등록 없음과 시작한 1분당 1크레딧을 명시하고 한국어 플랜 용어를 정리한다.
- 개인정보처리방침 한·영 시행일과 변경 이력을 표시한다.
- 복습 노트는 질문 제목을 정리하되 저장된 답변·연습문제 조건과 정답·그래프 데이터를 원문에서 재사용한다. 기존 노트는 다시 만들면 적용된다.

## 녹음 파일 업로드

기존 운영 환경에서 콜백 주소와 검증 비밀키 설정이 누락되었고, 파일 전체를 웹 함수로 전송하는 방식은 운영 요청 크기 제한에 걸렸다.

인증·동의·크레딧·소유권을 확인한 뒤 짧은 유효기간의 업로드 권한을 발급한다. 브라우저는 비공개 저장소로 파일을 직접 전송하고, 서버에는 업로드 식별자만 보낸다. 실제 파일 전체를 FFmpeg로 검사하고 측정한 길이로 크레딧을 예약한 후 받아쓰기를 요청한다. 중복 요청과 끊긴 업로드 재개를 지원한다.

한도는 원본 200MiB, 변환 결과 256MiB, 길이 3시간이다. 저장소 파일을 공개하거나 클라이언트의 재생 길이를 과금 근거로 사용하지 않는다. 새 DB 변경은 `20260911050000_audio_direct_upload.sql`이다.

## 검증 결과

- 최종 전체 테스트 922개, typecheck, 로컬 배포용 webpack 빌드 통과.
- 녹음 사전 점검·릴레이 단위 테스트 54개 통과.
- 실제 workerd 네트워크 검사 4개 통과: 기본 연결, 65초의 1분 경계, 버퍼 순서·재연결, 느린 제어 응답. 음성 공급자는 모킹하고 합성 PCM을 사용했다.
- 실제 격리 PostgreSQL에서 마이그레이션 및 20개 동시 요청의 할당·잠금·중복 방지·일일 한도 검증 통과.
- 업로드 API·콜백·디코더 관련 72개 통과. 실제 FFmpeg로 5.76MB WAV와 75초 7.2MB 합성 음성을 변환했다. 후자는 75,000ms, 2크레딧으로 계산된다.
- 실제 로컬 Chrome에서 빈 검색 복구, MacBook Pro 마이크 이름·입력 음량·소리 감지 및 확인 종료, 1,000자 안내, 종료 수업의 설정 진입을 확인했다. 테스트 질문은 전송하지 않고 지웠다.
- 녹음 활성 연결 0건과 확인용 마이크 종료를 확인하고 개발 서버를 전체 재시작했다. 새 브라우저 문서를 열었으며, 재시작 후 실제 localhost HTTP의 CSP·권한·릴레이 점검이 통과했다. 변경 전 운영 URL 점검도 통과했다.
- 전체 검사 중 기존 PDF 과량 텍스트 사례에서 한 차례 UNKNOWN TypeError가 발생했다. 해당 테스트 5개, 동일 실제 워커 20회, 전체 922개 재실행이 모두 통과했다. 원인은 재현되지 않았으며 파서를 임의 수정하지 않았다.

## 운영 반영 상태

사용자가 운영 설정·DB 변경·배포·실제 변환 및 테스트 데이터 정리를 명시적으로 승인했다. 기존 Vercel `lecue` 운영 환경에 `SITE_URL=https://www.lecue.app`과 기존 로컬 콜백 비밀키를 등록했다. 비밀키를 출력하거나 회전하지 않았다. DB 변경은 실제 운영 트랜잭션 검증 후 동일 SQL을 적용했다.

운영 배포: `dpl_56sjSggsJ2jiXmzoi7mJDLDtNvRu`, `https://www.lecue.app`. 배포 복사본 `/private/tmp/lecue-learning-release-zkgj14du`의 소스 415개 SHA1이 실제 배포 소스와 모두 일치한다. 후보 및 최종 운영 도메인의 실제 HTTP 녹음 점검이 모두 통과했다. 공식 서명 업로드 경로의 CORS OPTIONS도 HTTP 200이며 운영 Origin·POST/PATCH·필요 헤더를 허용한다.

첫 실제 전송 검사에서 일반 TUS 주소가 서명 토큰을 검증하지 않아 HTTP 400을 반환함을 발견했다. Supabase 공식 예제·서버 소스를 확인해 `/storage/v1/upload/resumable/sign`과 공개 API 라우팅 키를 사용하도록 수정하고 전체 테스트 922개·typecheck를 다시 통과한 뒤 최종 배포했다. 토큰은 같은 Origin과 서명 경로에만 전송한다. 근거: [공식 서명 업로드 예제](https://github.com/supabase/supabase/blob/master/examples/storage/resumable-upload-signed-uppy/index.html), [서명 경로 처리](https://github.com/supabase/storage/blob/master/src/http/routes/tus/lifecycle.ts).

실제 공급자 1차 검사: 전용 테스트 계정으로 7,200,044바이트·75초 합성 음성을 전송했다. TUS POST·HEAD·PATCH, 실제 파일 검증, 실제 공급자의 콜백이 완료돼 수업에 14개 구간이 저장되었다. 합성 음성의 기준 단어 4개가 모두 일치했고 2크레딧만 정산됐다. prepare·complete·종료 콜백을 반복해도 기록·과금이 늘지 않았다. 이 검사는 서명 경로 보정을 사용했으므로 최종 배포에서 다음 2차 검사를 별도로 수행했다.

**최종 운영 검사 통과:** 새로운 전용 계정에서 API가 반환한 주소를 그대로 사용하고, 실제 `app/classroom/audio-transfer.ts`와 설치된 `tus-js-client`로 전송했다. 주소 보정은 사용하지 않았다. POST 201, PATCH 204, HEAD의 7,200,044바이트 확인, complete 202, 실제 공급자의 콜백 완료를 확인했다. 75,000ms, 구간 14개, 합성 음성 기준 단어 4/4, 예약·정산·차감 각 2크레딧이 일치했다. prepare·complete·콜백 재시도 후에도 결과가 같았다. 테스트는 Node Buffer 전송을 사용했으며 테스트한 앱 helper의 SHA256은 `ed8a407669be5ce360a4da2b7ecfd76b52865d679e4a456be03cb3a17a9971f1`이다.

검증 후 두 전용 계정·관련 DB 기록·저장소 객체를 모두 삭제하고 테스트 비밀번호와 서명 전송 정보를 로컬 상태 파일에서도 제거했다. 안전한 결과 보고서: `/private/tmp/lecue-audio-direct-final-smoke/results.json`.

자료 전용 실제 HTTP 검사도 통과했다. 별도 초안에 TXT를 첨부하고 음성 0개 상태에서 실제 AI 답변·정답·자료 출처·질문 저장을 확인했다. 제목 유지, 비공개 미리보기, 교체 전 원본 보존, 삭제 후 404를 확인했다. 생성한 자료·수업 및 첫 테스트 계정을 모두 정리했다.

실제 마이크/탭 소리의 시작·일시정지·재개·종료 전체 인식 검증은 이번 변경에서 수행하지 않았다. 실제 마이크 준비 확인, 합성 PCM workerd 검사, 실제 공급자의 녹음 파일 변환은 각각 구분된 검증이다. 브라우저 파일 선택기는 확장의 파일 접근 제한 때문에 실행하지 못했으며, 파일 전송은 실제 업로드 helper와 실제 네트워크로 검증한다.
